# Excellence north star (orientation — forever)

## Aspiration (honest)

This playbook aims to become the **most professional, reusable planning → implementation method** for human + AI software teams — a bar so clear and so hard to copy that later templates look thin beside it.

That is a **trajectory**, not a claim that today’s files are already “#1 in history.” **One prompt cannot finish it.** Every future edit is one ratchet click toward that bar — or it should not land.

## Why this playbook exists (purpose — hard)

**One sentence:** gather everything useful for building software into **one** living reference so an AI agent can execute **fast** and still ship at **high quality**.

Agents already supply **speed**. They do **not** automatically supply **judgment, rails, stack craft, day loops, security, contracts, or lessons** unless those live where the agent can load them. Scattered tips in chat memory fail; a single playbook succeeds.

### What “everything useful” means

| Include | Examples (generic) |
|---------|-------------------|
| Method | Delivery, day loop, CI/CD, FEATURE_SDLC, prompts, lessons |
| Judgment | Outside methods absorbed as craft — never second constitutions |
| Stack craft | `technologies/` packs that grow as languages/frameworks are added |
| Templates | Skeletons a new planning product can copy |
| Adjacent ship craft | Brand/logo, imagery, motion/video, SEO/GEO — **when they serve shipping software**, not as a random media library |

If it helps a human+AI team **plan or build software** (including AI products and software-backed businesses), it belongs here in a forever-generic form. If it only serves one product’s gossip or tracker URLs, it belongs in that product’s `docs/OWNER_STANDING.md` — not in method/`templates/`.

### Who it must serve

The same playbook must work for:

1. **Hands-off agent coding** — the owner mostly supervises; the agent executes end-to-end against this reference.
2. **Professional / revenue products** — real users, money, PII, compliance; full rigor and evidence (proportional depth still applies — SF-08).
3. **Anything in between** — prototypes, tools, APIs, studios — as long as software is being built.

Do **not** fork a “vibe” playbook and a “serious” playbook. One method; rigor scales with risk.

### How agents use this purpose

When the owner says “add X to the playbook / raise professionalism”:

1. Ask: does X make the **single reference** stronger for the **next** software build (speed **and** quality)?
2. If yes → atlas → deepen or add → wire → sync (SF-14).
3. If it is vanity, duplicate, or lowers a rail → Candor refuse (SF-07).

The dream is the **strongest reusable software-building playbook** we can grow over time (more languages, more craft, more lessons) — never a finished one-shot dump. Trajectory: [`EXCELLENCE.md`](EXCELLENCE.md) ratchet + [`coverage/`](coverage/README.md).

## What “best” means here (dimensions)

Score a change against these — not against marketing adjectives:

| Dimension | Best looks like |
|-----------|-----------------|
| **Speed × quality** | One reference makes agents fast **and** high-quality; chat memory alone is not enough |
| **Safety rails** | SECURITY / COMPLIANCE / ethics / candor hold; High risk is named and treated |
| **Evidence** | Done needs proof (tests, CI, contract); no checklist theater |
| **Proportional rigor** | Small products stay light; rigor grows with money/PII/API/public/booking (SF-08) |
| **Agent-operable** | Context hygiene, handoffs, memory pointers; rules fit an LLM session (SF-09) |
| **Forever-generic** | No product names, people, or tracker URLs in method/`templates/` |
| **Deepen-over-duplicate** | Coverage atlas first; one home per practice; % stays honest |
| **Always-Current** | Touched homes stay fresh this session; official/Context7 evidence; freshness CI gate ([`07-judgment/playbook-freshness.md`](07-judgment/playbook-freshness.md)) |
| **Harness breadth** | Popular AI agents/IDEs (US + China + cloud chat) have honest % + packs ([`coverage/08-ai-agents.md`](coverage/08-ai-agents.md), [`agents/`](agents/README.md)) |
| **Operable day loop** | Start once → finish must-finish → closeout → Pareto + handoff |
| **Company seats** | Org chart, goal ancestry, atomic checkout — studio feels like a firm ([`07-judgment/studio-company.md`](07-judgment/studio-company.md)) |
| **Software Factory line** | Intake→triage→plan→build→independent review→Done with evidence ([`07-judgment/software-factory.md`](07-judgment/software-factory.md)) |
| **Transferable lessons** | Real surprises become one sharp playbook bullet when the next product benefits |

A change that raises vanity (more files, louder claims) without raising a dimension **fails** the bar.

## Ratchet protocol

The step-by-step procedure for every factory or template change lives in [`CONTRIBUTING.md`](CONTRIBUTING.md) § Changing the factory; this file defines the dimensions that procedure must raise.

**Ratchet rule:** never ship a change that makes the next product *less* professional than before. Prefer skip over a noisy “upgrade.”

## How we get there over time

| Cadence | What happens |
|---------|----------------|
| **Owner asks to add/improve X** | Atlas → ratchet → deepen or add → sync |
| **Implementation day surprise** | Lesson capture when quality bar met (`08` § Lesson capture) |
| **Thin atlas rows (⚠️ / low %)** | Prefer upgrading those homes over inventing new domains |
| **External methods appear** | Judgment-only absorb (`07-judgment/`); never a second OS |

Progress is **visible** in: rising honest coverage %, fewer ⚠️ rows, sharper lessons, fewer silent agent failures — not in word count.

## Anti-patterns

| Do not | Why |
|--------|-----|
| Claim “best in the world” as a shipped status | Aspiration ≠ evidence; honesty is part of excellence |
| One mega-rewrite to “finish” the dream | Context overflow + unreviewable diff; use the ratchet |
| Add parallel docs for the same practice | Dilutes the atlas; agents ignore both |
| Copy a course / agent kit wholesale into the repo | Second constitution; see judgment README |
| Thin a full-cadence product by citing “flexibility” | SF-08 pin; excellence includes knowing when rigor is earned |
| Edit a vendored copy “just this once” | Local forks drift from the factory and stop receiving fixes |
