# English — UI / UX

English UI can still be secondary to Arabic (or another) market default — check product SEO/locale defaults.

## Must

- html lang=en dir=ltr unless embedding other scripts
- Pick one regional default for the product (en-US vs en-GB) for dates, spelling, and currency examples — document it in DESIGN
- Plain language; avoid idioms that fail for non-native readers when the audience is global
- Sentence case vs Title Case: follow the product DESIGN consistently

## Avoid

- Mixing color/colour and mm/dd vs dd/mm in the same product without locale tags
- US-only assumptions (ZIP, state) on global forms

## Review prompts

1. Does the first viewport read correctly in LTR?
2. Is address/tone (formal vs informal) consistent?
3. Do strings fit without clipping after translation expansion?
